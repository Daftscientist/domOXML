# PROTOTYPE — UI directions for the view (delete when one wins)

Question: what should the domOXML MCP App view look like? The first pass (default toolbar, grey well, hairlines) was
rejected by the user as ugly and boring. Three structurally different directions, switchable on the dev harness with
`?variant=A|B|C` (no param = the first pass) and a floating switcher (dev only).

- A — Paper: the deck as a physical stack of paper on an ambient backdrop tinted by the slide; floating glass tools.
- B — Stage: cinematic, story-style card; slide edge to edge, progress segments, tap to flip; assistant as a caption.
- C — Canvas: multiplayer board; slides as artboards, floating tool dock, sticky-note comments, assistant as a cursor.
